# FRAGZONE

Каталог игровых серверов. Ветка `feature/site-support-system` добавляет полноценную систему поддержки непосредственно на сайт без Telegram.

## Система поддержки
- Гость может отправить тикет без регистрации и получает секретную ссылку для просмотра.
- Пользователь регистрируется/входит по email и паролю, видит свои обращения и комментирует только собственные тикеты.
- Администратор входит отдельно на `/support/admin.html`, просматривает обращения, меняет статусы и приоритеты, отвечает в переписке.
- Пароли хешируются PBKDF2-SHA256 (210 000 итераций); старые хеши с 100 000 итераций также принимаются. Сессии используют HttpOnly/Secure cookie, в D1 хранится хеш токена.

## Установка на Cloudflare Pages
1. Создайте D1 Database.
2. Выполните `schema.sql` в D1 Console либо `npx wrangler d1 execute <DB_NAME> --remote --file=schema.sql`.
3. В Pages → Settings → Functions → D1 database bindings создайте binding с Variable name `DB`.
4. Добавьте Pages variables/secrets: `ADMIN_EMAIL` и Secret `ADMIN_PASSWORD_HASH`.
5. Сгенерируйте хеш пароля администратора: `node scripts/make-admin-hash.mjs 'длинный-пароль-от-10-символов'`.
6. Скопируйте вывод команды в Secret `ADMIN_PASSWORD_HASH` и выполните deploy после слияния ветки.

## Адреса
- `/support/` — создать обращение.
- `/support/auth.html` — регистрация и вход.
- `/support/my-tickets.html` — личные обращения.
- `/support/admin.html` — вход администратора.

Перед публичным запуском рекомендуется подключить Turnstile/rate limiting, подтверждение email, восстановление пароля и почтовые уведомления. Секретная ссылка гостевого тикета пока показывается на экране и не отправляется по email.


## Расширенная система администрации (OWNER CONTROL)

После обновления выполните миграцию D1 **до публикации новой версии**:

```bash
npx wrangler d1 execute <DB_NAME> --remote --file=migrations/2026-11-admin-system.sql
```

Владелец определяется через Secret/Variable `ADMIN_EMAIL`. Владелец входит через `/support/owner.html`. Сотрудники входят обычным способом через аккаунт на сайте и получают доступ к `/support/admin.html` после назначения уровня владельцем.

Уровни доступа:
- 0 — пользователь;
- 1 — Helper: тикеты и ответы;
- 2 — Moderator: тикеты и мут;
- 3 — Senior Moderator: внутренние заметки, журнал и просмотр наказаний;
- 4 — Administrator: баны;
- 5 — Head Administrator: WARN и снятие наказаний;
- OWNER — полный доступ, выдача уровней, настройки и управление безопасностью.

Новые API для наказаний используют D1-таблицу `punishments`: активный бан блокирует вход, активный мут блокирует отправку тикетов и сообщений. Все выдачи наказаний, изменения уровней, настроек и тикетов записываются в `audit_logs`. Режим обслуживания применяется middleware ко всему сайту (владелец сохраняет доступ), регистрация и приём новых обращений блокируются на API, объявления показываются на главной странице.

Важно: после применения миграции проверьте вход владельца, вход сотрудника каждого уровня и действия на тестовых аккаунтах. API автоматически создаёт недостающие таблицы, но применение миграции заранее остаётся рекомендуемым шагом для Production.
